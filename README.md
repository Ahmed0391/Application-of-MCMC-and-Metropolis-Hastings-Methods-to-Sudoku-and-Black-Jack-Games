# Monte Carlo and MCMC Methods: Sudoku & Blackjack

This project explores the use of **Monte Carlo methods** and **Markov Chain Monte Carlo (MCMC)** techniques through two probabilistic problems:

1. **Sudoku grid resolution** using simulated annealing.
2. **Blackjack game simulation** to evaluate different player strategies through repeated Monte Carlo simulations and probabilistic state transitions.

The project was developed as part of a study of probabilistic and stochastic methods, with the objective of applying these techniques to structured and stochastic problems.

---

## Project Overview

### Part I — Sudoku Grid Resolution

Sudoku is a constraint satisfaction problem in which a 9×9 grid must be filled so that every row, column, and 3×3 subgrid contains the digits 1–9 exactly once.

Rather than solving the puzzle deterministically, we formulate Sudoku as an **optimization problem** and use **simulated annealing**, a stochastic optimization technique related to MCMC methods.

The objective is to find a configuration with an energy of:


E_{grid} = 0


where zero means that all Sudoku constraints are satisfied.

### Part II — Blackjack Simulation

The second part applies Monte Carlo and MCMC ideas to the game of Blackjack.

The program simulates multiple games under different player policies and collects statistics on wins, losses, and draws. A probabilistic acceptance criterion inspired by the **Metropolis-Hastings algorithm** is also used to explore possible game states.

# Part I — Sudoku Resolution

## Problem

The algorithm starts from a partially completed 9×9 Sudoku grid.

The initial grid is completed so that each 3×3 subgrid contains all digits from 1 to 9. At this stage, row and column constraints may still be violated.

The algorithm then progressively modifies the grid until all constraints are satisfied.

## Method

The algorithm follows these steps:

1. Represent the Sudoku as a 9×9 matrix containing fixed and empty cells.
2. Fill the empty cells so that every 3×3 subgrid contains the digits 1–9.
3. Randomly select a 3×3 subgrid.
4. Select two cells that were originally empty and swap their values.
5. Compute the energy of the current and proposed configurations.
6. Apply the simulated annealing acceptance criterion.
7. Reduce the temperature after each iteration.
8. Continue until the energy reaches zero or the maximum number of iterations is reached.

### Energy Function

The energy measures the number of constraint violations in the grid:


$$
E(\text{grid}) =
\sum_{i=1}^{9}\left(9-\left|\mathrm{unique}(\text{row}_i)\right|\right)
+
\sum_{j=1}^{9}\left(9-\left|\mathrm{unique}(\text{column}_j)\right|\right)
+
\sum_{k=1}^{9}\left(9-\left|\mathrm{unique}(\text{subgrid}_k)\right|\right)
$$

A lower energy corresponds to a configuration satisfying more Sudoku constraints.

The target is:


E_{grid} = 0


which corresponds to a valid Sudoku solution.

## Simulated Annealing

For a proposed configuration, the acceptance probability is:


\alpha =
\min\left(
1,
\exp\left(
-\frac{E_{{proposed}-E_{current}}{T}
\right)
\right)


If the proposed configuration improves the energy, it is accepted with probability 1.

Worse configurations can also be accepted, particularly at high temperatures. This allows the algorithm to escape local minima.

The temperature is progressively reduced according to:


T_{n+1}=0.99T_n


using a cooling rate of `0.99` in the current implementation. :contentReference[oaicite:1]{index=1}

## Neighborhood Generation

A neighboring configuration is generated by selecting a random 3×3 subgrid and swapping two cells that were initially empty. This preserves the property that each subgrid contains the digits 1–9.

The implementation performs this operation in `genererNouvGrille.m`. :contentReference[oaicite:2]{index=2}

## Implementation

The Sudoku solver is divided into several MATLAB/Octave functions:

| File | Description |
|---|---|
| `main.m` | Defines the initial Sudoku grid and runs the algorithm |
| `initialisationGrille.m` | Initializes the empty cells while preserving fixed values |
| `genererNouvGrille.m` | Generates a neighboring configuration |
| `E.m` | Computes the energy of a grid |
| `critere.m` | Performs the simulated annealing procedure |

The initialization function fills the non-fixed positions in each 3×3 block using a randomized permutation of the missing values. :contentReference[oaicite:3]{index=3}

The energy function evaluates the constraints associated with rows, columns and 3×3 blocks. :contentReference[oaicite:4]{index=4}

##  Monte Carlo Analysis

Because the algorithm is stochastic, different executions can require different numbers of iterations.

To study this variability, the solver was executed:


M=100


times using different random seeds.

Let $N_i$ denote the number of iterations required during execution \(i\).

The empirical mean is:

$$
\bar N =
\frac{1}{M}\sum_{i=1}^{M}N_i
$$

and the empirical variance is:

$$
\sigma^2 =
\frac{1}{M}\sum_{i=1}^{M}(N_i-\bar N)^2
$$

For the experiment, we obtained:

$$
\bar N = 431.96
$$

with a standard deviation of approximately:

$$
\sigma = 355.02
$$

Using the normal approximation, the estimated 95% confidence interval is:

$$
\bar N
\pm
1.96\sqrt{\frac{\sigma^2}{M}}
$$

giving approximately:

$$
[362.06,\;501.86]
$$

This experiment illustrates the variability introduced by the stochastic nature of the algorithm.

# Part II — Blackjack Simulation

## Problem

The second part of the project applies Monte Carlo and MCMC ideas to Blackjack.

In the game, a player competes against a dealer. Each participant initially receives two cards and can subsequently draw additional cards or stop.

A hand exceeding 21 points results in a loss.

The simulation aims to study different player decision policies by repeatedly simulating games and collecting statistics on their outcomes.
